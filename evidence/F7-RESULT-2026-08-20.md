## 2 · The two caveats, recorded

🔴 **(a) The validator-identity flag is an artifact of self-testing.** Every served recipe reads
`validated_by: farseen (github: FarseenSh)` — and **the person running the stranger test is the
person who signed the recipes.** The *stranger* property this test exists to prove is therefore
weaker than the table looks: it proves a clean **config** reaches a working surface, not that a
**stranger's judgement** finds the answers trustworthy. **The first genuinely external run is still
ahead of us.**

⚠ **(b) Q10's `0 / 8` pinned is the provenance model WORKING, not a miss.** `dynamic` is
**artifact-sourced** (C51/C54): the SDK is closed-source, the `dynamic-labs` org publishes **zero**
public repos, and there is **no repository to pin a commit against**. Its citations are versioned
npm/CDN paths, which is the strongest re-fetchable form that exists for it. **Scoring it as a
citation failure would penalise the one class the artifact rule was written for.**

## 3 · 🔴 Q7 — DIAGNOSED. It is the surface, not the retriever, and it is the one launch-relevant find

**The row:** *"how do I implement an ERC-4626 tokenized vault"* → **spec only, no recipe**, while M1
counts `erc-4626` **DIRECT-reachable**.

**Reproduced, and it is neither instrument being wrong about the other:**

| call | recipe |
|---|---|
| `{query, intent: "integrate"}` | ✔ **`erc-4626@final` served** |
| `{query, intent: "debug"}` | 🔴 NONE |
| `{query, intent: "lookup"}` | 🔴 NONE |
| `{query}` — **intent omitted** | 🔴 **NONE** — and the payload echoes `intent: "lookup"` |

**`intent` defaults to `lookup`, and the recipe arm fires only on `intent: "integrate"`.**
Both phrasings (`ERC-4626` and `erc-4626`) serve the recipe when the argument is passed, so **M1 and
the live surface agree** — the difference is the **argument**, not the surface. **This is not F54's
shape.**

🔴 **The root cause is in the registered surface:**

```
intent: { type: 'string', enum: ['integrate', 'implement', 'debug', 'lookup', 'learn'] }
```

**Five values and no description.** Nothing tells a model that `integrate` is the one that unlocks
the human-validated recipe — the moat. The client guessed right **nine times out of ten** from the
word alone, and the tenth is Q7.

⭐ **Golden rule 12 named this in advance:** *"tool descriptions are an eval subject — wording
measurably swings activation rates."* This is that, on the field that gates the product's
differentiator.

⚠ **And it means M1's `24 of 24` is measured under an argument a real client may not send.** M1's
probe hardcodes `intent: 'integrate'`. **The probe is optimistic relative to real traffic**, and
that is now recorded beside its number.

**`content_rescue: true` on this row is a second, separate fact:** the identifier arms returned
**zero** hits for that phrasing, and all ten spec units came from the content-column rescue. So Q7's
payload is *rescued spec units with no recipe* — the thinnest form of a right answer.

🔴 **Not fixed here.** A description added to `intent` changes the registered surface, which is
**≤600 tokens and an eval subject** — a wording change needs a measured activation run, not a
launch-morning edit.

## 4 · Q5 — both halves attributed to their class

Reproduced: the sentence appears **only when the caller passes `version: "70bc2e40"`** — which the
client did, having read the stamp off the recipe in the first call.

### (b) All ten hits from `Uniswap/v3-core` for a **SwapRouter02** question — a COVERAGE gap

Measured: the corpus holds `uniswap-v3` · `uniswap-v4` · `uniswap-v4-periphery` · `uniswapx`, and
**`uniswap-v3`'s units are `Uniswap/v3-core` only. There is no `v3-periphery` in the corpus.**
SwapRouter02 lives in periphery.

**Scoping is correct** — `project: uniswap-v3` returns `uniswap-v3` units, and in this corpus that
*is* v3-core. ⭐ **The gap is that the id `uniswap-v3` denotes the CORE REPO while a developer
saying "Uniswap v3" means the protocol, periphery included.** Same family as F73: one name covering
less than the reader assumes.

⚠ **The typed tables already know SwapRouter02** — deployments on ethereum/arbitrum/base and an ABI
row. **`web3_lookup` answers it; `web3_search` has no source units to cite.** That split is worth
naming: F-4's tables and the unit corpus have different coverage, and a caller meets whichever the
question routes to.

🔴 **Reported as coverage (F52's class), never scored as retrieval**, and ingest is recipe-driven
(R-W) — so `v3-periphery` is a proposal, not a task.
