## 2. ⭐ What the run establishes that no previous run could

**Clause 2 PASSED, and it was the predicted danger.** Rule 6a calls expansion *"the arm most likely
to smear version boundaries"*; the gate exists chiefly to catch that. Measured with the real model on
the real corpus: **intrusion moved −0.03pp.** **Expansion did not cost version separation.**

⚠ **That is a pass on the clause, not a verdict** — clause 4 fails, so no verdict may issue on
clause 2 at all (D17). *"It did not smear versions"* is descriptive at n=788.

**Clause 3 is what actually killed it: 0.00pp.** Not negative. Zero.

🔴 **Zero is the signature of an inert column, so it was checked rather than reported.** The
treatment weights `expansion_prose` at **0.4** and the control at **0.0** — correct — and on five
prose-shaped queries the treatment's **top-10 changed on 5 of 5**. **The column is live; the effects
cancel.** Expansion helps some probes and hurts others in equal measure on this probe set.
**Changed, not better** (rule 11).

⚠ **And a limitation of the gate for clause 3, stated because it decided the outcome:** the probes
are **verbatim headings taken from the prose units themselves**, so the target already matches
`content` at weight 1.0. That probe set was designed to measure **intrusion**, and it measures
**recall gain** poorly — the case expansion is least able to help is the case it was scored on.

## 5. FOUR defects in my own instruments, each caught by running it — with its falsification

🔴 **The gate first ran on the WRONG CORPUS.** `check-expansion-intrusion.ts` hardcoded
`generated/stage-a` (188,526 units, pre-wave-1) while the fill covers `stage-a-full` (572,997), so
**only 61,795 of 157,582 expansions applied** — a treatment arm 61% absent, reporting a clean-looking
FAIL. Fixed with `--in`; re-run on the matching corpus. **Both runs are in the record.**
**Falsified:** the run prints the applied-expansion count against the sidecar's row count, and
pointing `--in` back at `stage-a` reproduces `61,795 / 157,582` rather than passing quietly.

🔴 **C1/C2 fired 243,679 FALSE leaks on their first run.** They asked *"does `scope_project` match
this term?"* and got yes for `contracts`, `aa`, `map`, and `scope_version` for `x`, `version` —
because **`unicode61` splits the scope columns' own content**: `openzeppelin-contracts` →
`openzeppelin` + `contracts`, `5.x` → `5` + `x`. Excluding terms that *equal* a project id was not
enough; a term can be a **token inside** one. Rewritten as a **treatment-vs-control difference**,
which needs no exclusion list and is strictly stronger. **A check that fires on healthy data gets
switched off, and the run it would have caught is the one after that.**
**Falsified:** with the corrected definition the poisoned corpus still reports C1 leaks and the
clean corpus reports 0 — the check distinguishes the two, which the first draft did not.

🔴 **The poison caught only C1.** C2 and C3 stayed silent — which reads as a pass and was an
**absence of a test**: two checks trusted because nothing had ever made them speak. Each now has a
counterexample shaped like its own failure mode, and the falsification **requires all three to
fire**. **Falsified:** `--poison` injects three rows; **3 of 3 fire**, and removing any one row
silences exactly its own check.

🔴 **The OZ anchor destroyed its own baseline on the post-gate run** — it routed around
`callTool`'s refresh with a raw fetch, sent an expired bearer, **graded the 401 `invalid_token`
body as `0 hits`**, and overwrote the byte-exact cached payload with 68 bytes. Recovered from the
repo's own history (`git checkout HEAD~1`). Full record and the three fixes:
`OZ-TRANSFER-HOOK-2026-08-18.md` §"THE ANCHOR DESTROYED ITS OWN BASELINE".
**Falsified both directions:** with a deliberately invalid token the anchor returns
**`REFUSED — HTTP 401`** and the baseline's SHA is **byte-identical before and after**; with a valid
token it returns the true reading. **F66's shape, produced by the instrument rather than the
server.**

⭐ **All four are one class** — *an error or approximation path reinterpreted as data*: a 61%-absent
treatment arm read as a treatment arm, a tokenizer split read as a leak, an unexercised check read
as a pass, and an auth refusal read as a retrieval result. **The shared void detector is still the
right fix**, and it is not built.
