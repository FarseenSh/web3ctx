# 17 — SOTA Review (Fable deep analysis, 2026-08-02)

**Status:** Independent design review · produced by 6 parallel research streams run 2026-08-02
**Method:** Full read of every doc in this repo by two audit agents + 4 external research streams (retrieval SOTA · competitive landscape · MCP design practice · Cloudflare stack), each grounded in dated primary sources, including **live probes run today**: Context7's index API, MCP `initialize` against 16 web3 docs domains, and `tools/list`/`tools/call` against Context7, Cloudflare docs, DeepWiki, and Microsoft Learn MCP servers.
**Objective function reviewed against (owner's, `15-` §0):** maximum accuracy · highest performance · lowest tokens — in that order.

---

## 0. Verdict

**The spine of this design is genuinely at — and in three places ahead of — the mid-2026 frontier.** The signal hierarchy (deps ≫ BM25 ≥ dense, no encoder on the primary path), the Layer-0 version pre-filter, complete-unit chunking, and the intrusion-rate headline metric all match the strongest controlled evidence published this year, most of which appeared *after* the design was locked:

- **"BM25 Wins at Scale" (arXiv 2607.26497, 2026-07-30)** found exactly this architecture — agent + ranked lexical discovery — is Pareto-dominant: agentic file-search alone costs **39× the tokens**; dense is below both at every corpus size; swapping raw grep for a BM25 top-5 tool moved 36.9 → 69.4 at 1/9th the tokens. *"Agentic reasoning works best after ranked discovery rather than in place of it."* This product **is** the ranked-discovery stage for a corpus agents cannot grep.
- **The wedge is verified empty.** A live probe of Context7's index today returned **`versions: []` on every web3 library tested** (wagmi, viem, Aave, OZ, Foundry, Solidity, Uniswap, Base, Solana). No product in the landscape does entity→version binding, and **nothing anywhere has dependency closure**. The problem is quantified: 25–38% deprecated-API rates across 7 LLMs (ICSE 2025), a 24-point accuracy cliff on post-cutoff APIs, 70–90% deprecated usage when fed deprecated context.
- **The intrusion-rate metric is ahead of the field.** No published benchmark uses it by name; the nearest analogs (EnterpriseRAG-Bench "traps", SACL asymmetric normalization, HELEA same-name negatives) confirm it is the right axis. Published with methodology, it would be the **first credible eval in the category** — no independent docs-MCP eval exists (the only head-to-head is co-marketed by its winner and predates Context7's rewrite).

**But "best MCP design ever, as written" is not yet true.** Three classes of problems, all fixable:

1. **~10 factual premises broke on verification** — including one golden rule (§2).
2. **The propagation claimed complete today is ~70–90% done**, and the implementation contract (`06-`) has type-level defects a builder would ship (§4).
3. **The market moved on packaging**: `grep`-over-docs is now free table stakes (8 of 16 web3 docs domains run first-party MCP servers today), recipes are being commoditized as free SKILL.md files, and the winning servers absorbed the search loop server-side. The retrieval design wins; the *surface* design needs Skills + tighter shaping to win the token axis (§5–6).

Bottom line by axis: **accuracy — category-leading once §6 fixes land; latency — achievable but the headline SLO should be demoted (it's 2.5–6× more aggressive than the only published measurement of this exact stack, and agent-trace evidence shows sub-second tool calls are ~1% of task wall-clock); tokens — the design loses today to Context7's measured 3.3k tokens/task bar unless the §5 changes land.** The moat thesis (curation + freshness + trust) survives everything and is strengthened by Context7's documented failures (non-reproducible LLM ingest, 6-month-stale flagship entries, ContextCrush injection).

## 2. Factual premises that broke (corrections C33–C44, in severity order)

| # | Was | Now (verified 2026-08-02) |
|---|---|---|
| **C33** | "LateOn-Code (149M)" as the late-interaction candidate | **No model named "LateOn-Code" exists.** The model is **LateOn** (LightOn, arXiv 2607.27178, 2026-07-29); there is no code-specific variant. Every downloadable ColBERT scores **50–63 on MTEB Code** (GTE-ModernColBERT 54.37, jina-colbert-v2 49.88); only mLateOn reaches 73.48. The no-late-interaction *decision* survives — but because **no good code ColBERT exists**, not because of hosting. |
| **C34** | Golden rule 2: "no serverless platform hosts late interaction" | **False since 2026-07-29**: turbopuffer serves ColBERT-style multi-vector in beta ($16/mo floor, BM25 1M-doc warm p50 13 ms, S3-backed). **The box-reinstatement trigger's destination is now turbopuffer at $16/mo, not a Hetzner box at €41+.** Vectorize remains single-vector — the Cloudflare constraint stands. |
| **C35** | Rule 6: Provence ON the hot path, "80–95% removal at zero marginal cost" | **Both numbers wrong.** The paper says **50–80%** (speedup measured at 49%); "zero marginal cost" holds *only when unified with a reranker* — this design has none, so it's a full DeBERTa-class pass on a 10 ms-CPU Worker. Provence is QA/English/prose-only, sentence-rounded, **never evaluated on code**. "Prompt Compression in the Wild" (arXiv 2604.02985): *"prompt compression adds latency without quality benefits for code generation."* → **Reverse the bet: Provence moves OFF the hot path** (expand/async, prose only). The token win comes from payload shaping instead (§5). |
| **C36** | W1 hypothesis: "does late interaction resist the *short-query* collapse?" | **Backwards.** MaxSim's documented failure mode is **long** queries (86–97% drop >20 words, architectural — arXiv 2604.09982); short-keyword robustness comes from exact lexical match. Late interaction's real edge is **OOD generalization** (LateOn: every late-interaction model holds/improves rank under decontamination while dense drops; 26-point MLDR gap on identical training data). → Restate W1: *"on version-confusable hard negatives and unseen ecosystems, does a late-interaction arm resist intrusion better than the single-vector arm?"* |
| **C37** | `bge-m3` as adequate dense fallback | **51.49 MTEB Code — second-worst dense model in LightOn's table**, ~25 pts below voyage-4-nano. Adequate for nothing we care about. See §6.3 for the replacement strategy. |

Measured agent queries (Hornet, BrowseComp GPT-5 traces): **median ~10 terms, keyword-dense, operator-heavy** — beyond human p99, not "short." And the locked 200 already average 13.3 words (≈18–22 tok) — the distinguishing property is **shape (keyword vs NL), not length**. Build the slice from the measured shape. Also: agent-shaped queries cost **~8.4×** more to serve at same p99 — feed that into W0 cost measurement M3. |
| **C40** | D1 distant-PoP latency = "the single biggest open risk" | **Largely solved, differently than feared**: D1 global read replication is free via the **Sessions API** (Australia 1,800 ms → 78 ms measured). ## 3. Design holes (not stale text — unresolved contradictions found by audit)

1. **Provence has no execution home** (both audit agents, independently). It's justified as "riding the rerank pass" — but D5 removed the reranker and the primary path invokes no model at all. Resolved by C35: off the hot path.
2. **Three-arm convex combination is outside its own theory.** TOIS covers two arms (flagged in the docs — good), but the deeper problem is that **a dependency-closure score is not a similarity distribution** — min-max normalizing a discrete reachability score into a convex combination is uncovered by any evidence. And HetDocQA (arXiv 2606.28367) found rank fusion delivers **no reliable gain** on exactly this corpus shape (code+markdown+prose). → Fix in §6.4: deps as **candidate-set definition**, BM25 ranks within it — which is Hydra's actual architecture and `15-`'s own "compose by role" taken to its conclusion.
3. **`06-`'s "never full bodies" guarantee is broken by its own types**: `IntegrateResult.code_chunks[].content` returns complete units from `search` for the majority intent (106/200 queries). Either `search` returns selector+snippet CodeChunks (add a `snippet` field, drop `content`) or the guarantee is false.
4. **No response ceiling exists anywhere on the surface** — no cap on `fetch.selectors[]`, no `deps` size cap (the `truncated` flag has no defined trigger), no snippet length, no token budget. For a product whose thesis is token efficiency, this is the most surprising omission. §5 fixes.
5. **`06-` type defects a builder ships as-is**: `retriever` enum has no value for the actual v1 retriever (still `"lateon-code" | "scar" | "bm25-fallback"` while §5.4 instructs `"lexical-fallback"`); `version_defaulted`/`last_validated` mandated on every response but absent from `CodeChunk`/`DocChunk`; `RecipePayload` puts `working_example` 7th against its own lead-with-example rule; no `parameter_list` field exists for the omit-parameters rule to act on; contentless-vs-external-content FTS5 never chosen (contentless cannot produce `snippet()` — the choice decides whether two primitives' output shape is implementable).
6. **The edge design depends on a spec era v1 doesn't serve by default.** `Mcp-Method`/`Mcp-Name` header routing and `ttlMs`/`cacheScope` are 2026-07-28-era features; v1 serves 2025-11-25 with the new era behind a flag. No doc states what the L0 edge cache does in the default configuration. (Also: SEP-2549 makes `ttlMs`/`cacheScope` required on **all** `*/list` and `resources/read` results, broader than `06-` says.)
7. **"106 of 200 never touch an encoder" does triple duty and two uses are inferred.** The routing table also sends `debug` (44) down the no-encode path (true count ≈150), and the figure silently assumes 100% Layer-0 symbol resolution — a rate never estimated. Measure resolution rate in W1; until then, state the number as the *derivation* it is.
8. **The intrusion-rate denominator is self-selecting** ("queries where both a TP and HN appear in top-10") — a system that retrieves fewer hard negatives shrinks its own denominator, making cross-system comparison invalid — and that comparison is precisely what Job B and the reinstatement trigger need. → §6.6: SACL-style protocol + report HN-recall alongside.
9. **E9 is closed on paper, open in fact.** `git init` ran; **zero commits exist**. The "locked" eval file is untracked. (Verified via `git log`/`git ls-files`.) The single cheapest fix in this document.
10. **Propagation residue** (fix list, by file): `01-` §3/§4/§5/§7/§8 (SCAR "pre-staged", LateOn-Code as v1 retriever, single-box latency); `02-` Feature-Set §1 + §5 + build-order tables (RRF/NextPlaid/Qdrant/SCAR/Valkey/LLMLingua, corrupted line 137, CCX33 figure); `03-` §7 ("Two meta-tools… ~400 tokens"); `05-` §2/§5.1/§5.2 (DenseOn→Qdrant, SCAR ghost boxes); `06-` §3.3/§3.4/§5.1 (types + "edge-17M draft path"); `08-` W6/DoD/R9/milestone-table ("LateOn multi-vector prose serving", LLMLingua, Hono/Bun, "Box up"); `09-` (R1a/R1b→FT1, "100–200 queries", unverified HAKARI-Bench citation); `10-` D4 (no supersession banner; reads as live), D7 consequences (still says DCR), C9-vs-C25 conflict; `11-` §1 (API-key-only auth — P5 named it), §5 ("/metrics on the box"), §6 (RRF + lateon↔scar seam test); `14-` header + closing line (still says "NOT yet propagated"); `HANDOFF.md` (points at the retired deck; "HB-2 effectively closed" understates ≥130 new slice items); `blockers/` playbook (missing P16 drift: CCTP fee-quote path, MetaMask rename, Circle Gateway, Permissioned Pools, ERC-8004, x402).

## 4. The competitive picture (all probed live today)

- **Context7 (60k★, 844k weekly downloads):** deep web3 coverage already — "we cover web3" is a false pitch. But `versions: []` everywhere, LLM-ingest non-reproducibility (#1855), resolver mis-picks as the admitted #1 failure (#1116), free tier cut 83% to 1,000 calls/mo, and ContextCrush (prompt-injection via indexed content — a warning that applies to us verbatim: **any server that puts third-party content into agent context needs an injection story for recipes/examples**). Their Jan-2026 rewrite set the public bar: **~3.3k tokens/task, ~3 calls, by moving filtering server-side and deleting caller knobs.**
- **Mintlify ($500M valuation, 20k customers):** every customer docs site gets a free hosted MCP (`search` + ripgrep-over-docs + skill.md). **8 of 16 web3 docs domains probed run one today** (Base, Circle, LayerZero, Privy, Tenderly, Chainstack, WalletConnect, Reown). → `web3.grep` is table stakes; **`web3.deps` has zero analogs and is the primitive to lead with.**
- **Skills are flanking the moat's packaging:** Alchemy routes application-code questions to its *skill* and reserves MCP for live data; Chainstack ships SKILL.md explicitly to avoid MCP token cost; wallet-integration recipes already exist as free skills (a5c-ai 509★). A skill costs ~100 tokens idle; five well-described MCP tools cost 2,500–3,500 registered tokens. → **Ship a Skill as the front door; the MCP is the version-bound retrieval backend it calls.** Context7 and MS Learn both ship MCP+CLI+Skill.
- **The doc-server norm is ≤3 tools** (Cloudflare 2 @ 250 tok, DeepWiki 3 @ 259, MS Learn 3 @ 951, Context7 2 @ 1,146). Five is defensible (AWS ships 5) but inherits AWS's obligation: a Tool-Selection-Guide `instructions` block. GitHub's negative result: dynamic tool discovery built, shipped as beta, **deleted 2026-05-20** — never build meta-tools; consolidation + URL-route surface selection won.
- **Exa's retreat is the null-hypothesis warning:** a well-funded search company built a code-context tool, measured it, and pointed users back to general web search. → The W1 eval keeps an honest **Context7 + plain-web-search baseline arm**, or the "beats everything" claim is unfalsifiable.
- **Demand reality:** best pure web3 docs-MCP traction found is 3,842 Smithery uses; the architectural twin (`dioptx/web3-docs`, same FTS5+BM25 thesis) has 11 stars and is dead; docs/ABI tools were 1.3% of calls in Blockscout's telemetry. → Validates deps/grep/eval-first sequencing; argues against early 750-project breadth. Category value is nonetheless real: the no-tool baseline scored **0/20** in the only published head-to-head.

## 5. The token axis, rebuilt on measured numbers

Current bar: **Context7 ≈ 3.3k tokens/task end-to-end.** The design as written loses to it (no response caps, full bodies in `IntegrateResult`, 5×~600-tok schemas ≈ 2,500–3,500 registered). To win:

1. **Registered surface:** Cloudflare-terse descriptions (target ≤500 tok total for 5 tools; their 2 tools = 250) + a Tool-Selection-Guide `instructions` block (~150–400 tok) + **Skill front door** (0 tok until invoked). Delete the "~400 tok" figure everywhere; publish the measured one.
2. **Delete caller knobs the frontier deleted:** Context7 removed `tokens`/`topic`/`page`/`limit` and cut responses 10×; MS Learn hides `topK`/thresholds ("Your API is not an MCP tool"). → Drop or demote `mode` and `max_results`; keep `scope`/`project`/`version` (they're Layer-0 inputs, not tuning knobs). Token budget moves to a **URL param** (`?maxTokenBudget=`), MS-Learn-style.
3. **Truncation contract:** `content_omitted: true` with `title`+`source_url` preserved (degrade bodies, never citations) + AWS-style self-describing cursor (*"call web3.fetch with start_index=N for more"*) + collapse-with-pointer-to-narrower-tool (`fetch` degrading into `grep`).
4. **Payload budget: ~4,000 tokens / top-5 chunks** (cAST's measured sweet spot; 8,000 made results *worse*). Hard caps on `fetch.selectors[]` (e.g. 10), `deps` unit inlining, snippet length.
5. **Fix the `IntegrateResult` body leak** (§3.3) — `search` returns selectors+snippets, period.
6. **Dual return** (`content` + `structuredContent`) — convergent practice; costs one field.
7. **Provence off the path** (C35); compact notation only for tool *results* where measured safe (−32% per "Notation Matters", accuracy-checked in W1).
8. **Measure tokens-to-task-completion** (`15-` §0's corollary is exactly right) against Context7's 3.3k bar — this becomes a headline eval number next to intrusion rate.

## 6. Revised architecture recommendations (expected value order)

**6.1 — Commit the repo. Today.** E9 is actually open; the locked eval artifact has no integrity protection. One command, highest importance-to-effort ratio in this review.

**6.2 — Re-decide the lexical home with a three-way W0 bake-off** (replaces "does FTS5 fit in 500 MB"):
- **(a) FTS5 in a *separate, dedicated* D1 database** — isolates the corruption blast radius, keeps the graph/typed DB exportable; time-travel restore is the documented recovery; external-content mode (snippets work, bodies in R2).
- **(b) Cloudflare AI Search** (ex-AutoRAG): shipped hybrid BM25+dense+RRF **with a trigram tokenizer Cloudflare recommends "for code"**, per-signal scores (a free ablation harness), and a built-in MCP endpoint; Cloudflare migrated their own docs MCP onto it. Counter-datapoint: that server measured **6,819 ms cold** — so it must be latency-qualified before it touches the hot path.
- **(c) turbopuffer** — BM25 warm p50 13 ms at 1M docs, regex index, sparse + multi-vector in one store, $16/mo; collapses the lexical + dense + late-interaction homes into one vendor and is the seam's new graduation path.
D1 keeps what it is uniquely right for regardless: **dependency graph (`WITH RECURSIVE`), identifier index, version predicates, typed tables — with no virtual tables in that DB.** Sessions-API read replication on from day one. Plus two ops lines for `11-`: a **circuit breaker on the ingest writer** (D1 has no hard billing cap; two documented ~$5k incidents) and retry/backoff on every D1 call (transient `D1_ERROR` is documented-normal).

**6.3 — Close the semantic gap at ingest, not at query time.** The 25–30 nDCG gap between BM25 and dense on prose queries (SPLADE-Code) is closed by **learned document-side expansion** — an offline Daytona job appending expansion tokens to indexed rows. Query stays plain BM25; no hot-path encoder. Do the same for identifiers (C42 sub-token expansion). Then re-examine the dense arm: benchmark whatever Workers AI actually offers against the prose slice; if nothing clears bge-m3 meaningfully, **drop the dense arm from v1 serving** and let expansion carry prose — removing the last encoder from the serving path entirely. (Job B's ablation matrix already decides this; add expansion-augmented-BM25 as an 8th configuration.)

**6.4 — Restructure fusion to dodge the three-arm theory hole:** dependency closure defines/expands the **candidate set** (a filter, not a scorer); BM25 ranks within it; convex combination α≈0.7 applies only where TOIS validated it — the two *similarity* arms on the prose path. This is Hydra's actual architecture and eliminates the graph-score-normalization problem. Keep the CC-vs-RRF measurement; add a fusion-vs-no-fusion arm (HetDocQA's null).

**6.5 — Restate the late-interaction question (C36) and re-scope the seam.** W1 companion run becomes: mLateOn / GTE-ModernColBERT vs the single-vector arm vs BM25 **on the hard-negative and per-language slices**, measuring intrusion. Second candidate mode: **mxbai-edge-colbert (17M, dim 48) as a reranker over BM25 top-50** — the deployment its authors recommend, small enough to plausibly run in a Worker. Reinstatement destination: turbopuffer, $16/mo (C34).

**6.6 — Harden the headline metric.** Fix the denominator (report intrusion **and** HN-recall; or fixed-candidate-set protocol); adopt **SACL's asymmetric-normalization measurement** (mean rank of correct-version doc when the wrong-version doc is better-documented — the documented mechanism *causing* version intrusion in dense retrievers: gold rank 87→288 from documentation density alone); mine negatives HELEA-style (same-name, different-referent). Set a numeric gate (today the headline metric gates nothing). Pre-register the protocol and publish it — first credible eval in the category, with Context7 + web-search baseline arms (§4).

**6.7 — Ship the Skill front door + keep an authless read tier.** SKILL.md drives the 5 primitives (Context7/MS Learn pattern); OAuth stays for the directory and paid tiers, but note every winning doc server (Cloudflare, DeepWiki, MS Learn) runs **unauthenticated** on the free read path — friction on a free docs surface is adoption tax. API keys stay REST/Docker-only (rule 9 intact).
Surface polish from the winning-server dissection: empty `prompts`/`resources` capabilities with no-op handlers (opencode treats `-32601` as fatal); arg-alias remapping before validation (models echo description phrasing — MS Learn's `question`→`query` rename broke 2–5% of requests); **tool descriptions become a W1 eval subject** (Microsoft: wording changes "swing tool activation rates materially"); trust fields in every payload (reputation/`last_validated`/version-provenance — Context7 already ships reputation fields; ours are better-grounded).

**6.8 — Demote the latency headline; keep the discipline.** Published measurement of this exact stack (Workers+D1 FTS5+Vectorize+KV): **<240 ms hit / <400 ms miss**. Agent traces (433k tool calls): sub-second tool calls ≈ 1% of task wall-clock; the directory has no latency bar. The real competitive axes are **tokens/turns per completed task** — where this design can win big. Keep sub-500 ms as the SLO, stop leading with <40 ms, and let W0 measure the replicated-Sessions path (C40) before any public number. `15-`'s own words stand: correctness + freshness first.

**6.9 — Sequencing confirmations:** deps+grep+eval before dense — **validated** (demand data, signal evidence, and the SPLADE finding all point the same way). Recipe authoring needs no corpus — start it W1 in parallel (14- §10.2's own suggestion; HB-1 staffing is still the gating item and remains open). Add the ~150-project P1 list as a real artifact (it doesn't exist; W2 has no input). Fold P16 ecosystem drift into the curator playbook (CCTP fee-quote path, MetaMask rename, Circle Gateway, Permissioned Pools, ERC-8004, x402 — the last two remain uncurated, in-lane, and are also the monetization rail).
